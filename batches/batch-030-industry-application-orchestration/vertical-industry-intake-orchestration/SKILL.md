# Vertical Industry Intake Orchestration

## When To Use

Use this skill when a user asks for an industry-specific AI application,
solution pack, workflow, assistant, operating system, or automation plan and
the request spans one or more verticals such as healthcare, clinical research,
legal, finance, education, manufacturing, real estate, commerce, SaaS, or
public-sector operations.

## Safe Workflow

1. Identify the industry, user role, workflow owner, target artifact, data
   sources, regulated touchpoints, and decision that the workflow supports.
2. Classify the request as advisory, research, operations, content, data,
   commerce, knowledge-base, customer-success, or software delivery work.
3. Route to existing trusted skills for domain execution instead of inventing
   industry claims: clinical review, finance operations, education planning,
   manufacturing QC, real-estate listing, commerce listing, source checking,
   privacy review, data quality, or RAG design.
4. Separate user-facing deliverables from specialist decisions. Do not provide
   medical, legal, investment, tax, regulatory, audit, or safety certification
   conclusions.
5. Produce an industry intake map that states assumptions, required evidence,
   selected trusted skills, excluded unsafe actions, and next verification
   gates.

## Expected Output

- industry and user-role profile
- workflow and artifact classification
- trusted skill routing map
- regulated touchpoint list
- missing evidence and specialist-review questions

## Verifier Expectations

- industry and role identified
- regulated-advice boundary check
- trusted-skill routing check
- missing data and evidence check

## Failure Handling

If the industry, data source, or regulated decision is unclear, stop at an
intake question list and avoid choosing a specialist conclusion path.
