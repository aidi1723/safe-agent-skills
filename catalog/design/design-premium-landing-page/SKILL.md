# Design Premium Landing Page

## When To Use

Use this skill when a landing page needs a premium, brand-specific finish beyond
generic template structure: strong first viewport, distinctive art direction,
conversion hierarchy, polished sections, responsive storytelling, and restrained
motion.

Use it with `content-seo-brief` for search and copy structure,
`content-claims-compliance-filter` for public claims, and browser verification
skills for screenshot evidence before release.

## Safe Workflow

1. Identify the page goal, audience, product category, conversion action,
   required sections, brand constraints, and source of truth such as `DESIGN.md`.
2. Use references such as Awwwards, Godly, Lapa Ninja, Cruip, Magic UI, and
   Aceternity UI only for pattern mining. Extract principles; do not copy full
   pages, proprietary copy, visual assets, or signature interactions.
3. Build a first-viewport signal that clearly shows the product, place, object,
   person, or offer. Avoid generic hero copy, stock-like atmosphere, and
   template-default cards or gradients.
4. Define section rhythm: hero, proof, problem or use case, product evidence,
   features, workflow, testimonials or logos, pricing or plan fit, FAQ, and
   final call to action as appropriate for the product.
5. Replace template fingerprints with product-specific typography, imagery,
   spacing, surfaces, iconography, component states, and interaction details.
6. Keep the page commercially useful: readable, fast, responsive, accessible,
   source-backed where factual, and easy to maintain.
7. Verify desktop and mobile screenshots, text fit, section hierarchy, calls to
   action, asset rendering, motion restraint, and public-claim risk before
   calling the page release-ready.

## Expected Output

- landing-page design brief or source-of-truth summary
- section and conversion hierarchy
- visual reference principles used, with copying boundaries
- implementation targets for layout, components, assets, and motion
- release-readiness notes for responsiveness, accessibility, performance, and claims

## Verifier Expectations

- build check for frontend code
- desktop and mobile screenshot check
- text overflow and overlap check
- accessibility spot check for contrast, focus, labels, and heading structure
- public-claim and source check for factual marketing statements
- performance or asset-size review when heavy media or animation is used

## Failure Handling

If brand, product, or audience context is missing, draft a minimal landing-page
brief with explicit assumptions before implementation. If requested references
encourage copied assets or inaccessible effects, restate them as design
principles and keep the implementation original, maintainable, and verifiable.
